# Plan: Jump to standard dumbbell sizes when adjusting weight

## Problem

MeasurementStepper in StrengthLog/ActiveWorkoutView.swift currently adds or subtracts 5 for pounds and 1 for every other measurement unit. Consequently, an entered weight of 22 lb becomes 27 lb or 17 lb instead of moving to an adjacent standard size. KeyboardAccessoryToolbar in StrengthLog/Components.swift independently performs the same additive adjustment, so changing only the visible buttons would leave inconsistent behavior.

## Scope and proposed behavior

Apply directional snapping to pounds and kilograms in the active/resumed workout weight controls, including both the inline minus/plus buttons and keyboard accessory buttons. Preserve arbitrary nonnegative values entered directly into the field. Do not snap on load, focus loss, unit changes, imports, or historical reads.

The request does not specify the gym's available dumbbells. Use the following explicit planning defaults, subject to product review before implementation:

- Pounds: 0, 5, 10, 15, 20, 25, ... (5 lb spacing).
- Kilograms: 0, 2.5, 5, 7.5, 10, 12.5, ... (2.5 kg spacing).
- Zero is the existing no-load boundary, not a physical dumbbell size. Decrement at zero remains zero; increment at zero selects the first positive size.
- Increment chooses the smallest size strictly greater than the current value; decrement chooses the largest size strictly less, clamped at zero. An exact size moves one full position.
- Apply the rule by weight unit to all weight fields, matching the task wording and the current unit-based control. Do not add equipment-dependent behavior in this change.

These are proposed application defaults, not a claim that all dumbbell racks follow these sequences. Low-weight sizes such as 3 or 8 lb, intermediate sizes, adjustable dumbbells, and metric racks with different spacing are not specified. If the intended behavior is a different sequence or dumbbell-equipment-only stepping, settle that before coding and update the acceptance examples below. Manual entry remains available for all such weights.

## Implementation outcome

- Added a shared directional numeric-adjustment policy in `StrengthLog/Components.swift`. It supports additive controls and standard weight intervals; pounds use 5 lb and kilograms use 2.5 kg. Boundary-aware snapping advances one full position for exact sizes, clamps decreases at zero, rejects non-finite values, and keeps integer formatting within safe conversion bounds.
- Wired both inline workout buttons and the keyboard accessory toolbar to the same policy. The toolbar receives the latest policy on view updates, so a live master-unit edit takes effect immediately. Reps and other existing toolbar users retain additive stepping.
- Measurement adjustments use the latest text-field value. Existing text-change handling continues to clear per-set measurement overrides and schedule persistence; direct entry remains unsnapped.
- Added `testWeightControlsJumpToStandardSizes` for pound and kilogram stepping, both control surfaces, live unit changes, off-size manual entry, a fractional kg screenshot attachment, and close/resume persistence.
- Updated the product requirements and interaction design documentation with the chosen intervals and exact-entry behavior.

Out of scope: configurable gym inventories, new settings, barbell plate calculations, automatic unit conversion, catalog edits, model/schema migrations, changes to PR/volume formulas, deployment, and rewriting existing workout history.

## Risks

- **Product ambiguity:** rack sizes and equipment applicability are unspecified. The proposed defaults make the plan executable but must not be represented as user-confirmed requirements.
- **Shared input regressions:** the toolbar also serves reps and last-set targets. Default additive behavior and focused regression checks are essential.
- **State synchronization:** UIKit text and SwiftUI model changes can diverge during rapid input or unit editing. Exercise both surfaces while focused and after dismissing the keyboard.
- **Decimal handling:** fractional kg sizes and off-grid imported values must not produce floating-point artifacts or integer-conversion crashes. Keep existing formatting expectations and test boundary values.
- **Persistence/history:** load changes currently clear set overrides. Preserve that behavior; do not introduce a bulk normalization or migration that alters untouched workouts.

Use scoped selectors, an available isolated simulator when necessary, and verify executed counts. Request sandbox escalation when required; never bypass restrictions or reset unrelated simulator data.
